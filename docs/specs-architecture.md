# Specs architecture

One scene source, two renderers. On ViroCore targets (iOS, Android, Quest,
PICO, visionOS, web) the JSX renders as Viro components. On SPECS the same
JSX compiles to a manifest that a Lens Studio host renders with Lens
SceneObjects, UI Kit and the Spectacles Interaction Kit. React, React
Native and ViroCore never run in the Lens.

```text
scene.tsx (Viro JSX, one source)
  |
  |-- ViroSpecsScene ............ runtime compiler, inside the app
  |-- viro-specs-compile ........ static compiler, CLI (Babel AST)
  |       both use components/Specs/core/ (transform, ids, animation, diagnostics)
  v
manifest v2  --validate-->  scene document (protocol 2)
  |                              |
  | json / scene-json            | --format lens-ts
  | (optional transport)         v
  |                         ViroGeneratedSceneHost.ts       <- @reactvision/react-viro ends here
  v                              |
ViroSpecsSceneControllerHost  <--+                           <- @viro-external/specs, in the Lens
  validate -> stage under a disabled root -> commit -> retire previous
  patch ops: create / update / remove / reparent
  asset registry, materials, placeholder for a missing asset (VS5003)
  SIK binding (7 phases), animations after assets load
  action registry, experience layer (lifecycle, placement, gaze)
  ViroSpecsHostDiagnostics (VS5xxx); never throws
  v
Lens Studio: SceneObject, Text, Image, RenderMeshVisual, UI Kit, SIK, WorldQuery
```

## Two producers, one contract

Both compilers call the same core in `components/Specs/core/`, so a
transform, ID or animation rule is written once.

| Producer | Input | Use it for |
| --- | --- | --- |
| `ViroSpecsScene` (runtime) | the live React element tree | apps whose scene depends on state; it recompiles on each render and sends the manifest through a `ViroSpecsSceneTransport` |
| `viro-specs-compile` (static) | the `.tsx` source, read with Babel | standalone Lenses with no phone or server; build-time checks in CI |

For the subset both handle, the outputs are byte-identical; the gallery
and golden suites assert it. The static compiler resolves imported
constants, spread props, `.map()` over a static array and ternary
visibility; anything else it cannot evaluate is a `VS2xxx` error with the
expression and its file:line.

The manifest is versioned (`version: 2`,
`schemas/viro-specs-manifest.v2.json`). Version 1 manifests are migrated in
memory with a `VS1002` warning. The scene document (`--format scene-json`)
is the manifest lowered for the Lens controller: scene protocol 2.

## IDs

A node's ID is its `viroTag`. Without one, the ID is a content hash of
kind, parent, ordinal and text or source, so reordering siblings does not
rebind callbacks to the wrong node. `--strict` requires `viroTag`
everywhere. The Lens names each SceneObject `viro:<id>`; LEAF scenarios
find nodes by that name.

## Diagnostics

Every producer reports a `ViroSpecsDiagnostic` with a code from one
catalog (`VIRO_SPECS_DIAGNOSTICS`): `VS1xxx` manifest validation, `VS2xxx`
static analysis, `VS3xxx` shared compile rules, `VS4xxx` features SPECS
does not implement, `VS5xxx` the Lens host. Severity is fixed per code.
The Lens host mirrors the `VS5xxx` codes, and the clean-consumer check
fails if the two packages disagree.
[specs-error-reference.md](specs-error-reference.md) is generated from the
catalog.

## The Lens host

`ViroGeneratedSceneHost` (generated by `--format lens-ts`) embeds the scene
document and calls `present()` on start and `clear()` on destroy. The
work happens in `ViroSpecsSceneControllerHost`:

1. Validate the document. A bad document is rejected with a code and the
   previous scene stays.
2. Stage the new scene under a disabled root.
3. Commit: enable it, retire the previous scene, dispose a failed staging.
4. Bind SIK one frame after commit. Interactions forward all seven phases
   with `source` = `hand-left`, `hand-right`, `gaze` or `synthetic`.
5. Start animations once every asset has loaded.

A later document is diffed by node ID into create, update, remove and
reparent operations, so a state change that edits one node touches one
SceneObject. Navigation and replacement cancel queued actions, deferred
SIK binding, delayed animations and asset loads that belonged to the old
scene.

## Actions and state

Callbacks do not cross into the Lens. A pinch becomes a typed action
(stable ID, payload checked against its declaration) that the Lens handler
registry runs standalone, or that a transport delivers to the app, where
`bindSpecsActionsToStore` reduces it into a Zustand store
([specs-actions.md](specs-actions.md)).

## Packaging boundary

| Package | Ships | Runs in |
| --- | --- | --- |
| `@reactvision/react-viro` | components, both compilers (`bin/viro-specs-compile.cjs` + `bin/specs-build/`), `viro-specs` CLI, schema | the app and Node |
| `@viro-external/specs` | `lens/` Lens TypeScript (production and validation files listed in `lens-runtime.json`), `sync`/`doctor`/`validate` scripts, portable `dist/` | Lens Studio and Node |
| `@viro-external/xr-contract` | renderer-neutral types | Node and the app |

`viro-specs sync|doctor|test|lab|go` in this package delegate to the scripts in
the installed `@viro-external/specs`. `viro-specs init <dir>` and
`viro-specs watch` run in react-viro (`src/specs-cli/`); `init` calls the
installed `sync` for the Lens runtime. `init --project <path>`, the old
Platform Lab bootstrap, still delegates and is now also `lab`. `specs:validate-lens` fails if any
Lens file imports `react`, `react-native` or a workspace package.
Architecture decisions are recorded in [adr/](adr/).
